02 / How I think

Good engineering should feel considered.

I like technical depth, but I care equally about whether the result makes sense to the person using it.

Understand

Start with the real problem.

I try to understand what the user or system actually needs before reaching for frameworks, patterns or complexity.

Build

Make the useful path work.

I prefer an end-to-end working experience over impressive pieces that never quite connect.

Refine

Notice the small things.

Errors, empty states, persistence, privacy, responsiveness and details are usually where software starts feeling trustworthy.
