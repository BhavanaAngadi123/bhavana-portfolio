Where Every Pet Belongs.

Live project ↗ GitHub ↗

A pet-first social and care platform where the pet has the public identity. The application brings profiles, posts, social connections, play dates, care reminders, memories, communities and account controls into one product.

Java 17Spring BootPostgreSQLREST APIsJavaScriptDockerRender
Problem

Pet apps often separate social life and care into disconnected tools.

I wanted a single product where the pet — not the owner — feels like the identity, while the owner quietly manages authentication and care behind the scenes.

Solution

I built an end-to-end Spring Boot application around persistent pet identities.

I designed owner-to-pet account relationships, REST APIs, PostgreSQL persistence, posts and social activity, profile-photo behavior, reminders, messaging, privacy controls and deployment on Render.

Trade-offs

I chose a strong working prototype over premature distributed architecture.

The current version uses a straightforward application architecture and browser-based image handling instead of introducing cloud object storage, event infrastructure and distributed services before the product needed them.

Next

V2 would focus on scale and real-time product behavior.

My next engineering steps would be cloud image storage, real-time messaging, stronger local discovery, production-grade observability and deeper automated end-to-end coverage.

A product detail I’m proud of:

When a pet changes its profile photo, that identity can update across the experience and appear as a social-feed moment. It is a small behavior, but it makes the product feel like a real pet social network instead of a collection of forms.

Data + LLM

LLM Text Chunking

GitHub ↗
PythonText ProcessingLLM Workflows
Problem

Long, unstructured text is difficult to pass directly into language-model workflows because context becomes noisy or exceeds practical input limits.

Solution

I built a text-preparation workflow that cleans content and creates manageable, context-friendly chunks for downstream prompting.

Trade-off

Chunk size improves manageability but can split related context, so the design balances chunk length with semantic continuity.

Next

I would compare fixed-size, sentence-aware and semantic chunking strategies using retrieval-quality measurements.

Applied AI

Prompt Chain Extraction

GitHub ↗
TransformersFLAN-T5Prompt Design
Problem

A single prompt can become unreliable when one request asks a model to identify multiple kinds of information at once.

Solution

I broke the task into chained prompts so each stage performs a smaller extraction step before passing structured context forward.

Trade-off

Chaining improves task separation but increases latency and gives earlier mistakes an opportunity to propagate into later steps.

Next

I would add structured-output validation and compare chained extraction against a single-prompt baseline on repeatable test data.

AI reliability experiment

Prompt Perturbation Analysis

GitHub ↗
PythonLLM EvaluationPrompt Analysis
Problem

Language-model outputs can change when prompts are modified in ways that appear insignificant to a person.

Solution

I explored controlled prompt variations and compared the resulting model behavior to understand sensitivity and consistency.

Trade-off

Qualitative comparison is useful for exploration, but it does not replace a larger evaluation set with explicit scoring criteria.

Next

I would formalize the experiment with automated test cases, semantic-similarity scoring and reproducible evaluation reports.
